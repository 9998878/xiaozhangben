# 小账本

一款给 iPhone 用的**纯本地记账 PWA**：没有账号、没有自己的后端服务器、数据只存在你这台手机的浏览器里，断网也能记账。

**在线地址（HTTPS，永久有效）** → <https://9998878.github.io/xiaozhangben/>

手机用 Safari 打开这个地址 → 分享 → 「添加到主屏幕」，之后就和一个 App 一样，飞行模式下照样能记、能看统计。

> 接手开发：先读 [AGENTS.md](AGENTS.md)；跑 `node scripts/status.js` 看当前状态。架构与取舍见 [docs/architecture.md](docs/architecture.md)，已知问题见 [docs/known-issues.md](docs/known-issues.md)，发版清单见 [docs/release.md](docs/release.md)，版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 2.39.0 更新了什么（账单体检）

「解读」页新增**账单体检**卡片：对整个账本的全部历史做一次本机检查，不联网，约 3 毫秒出结果。

1. **疑似重复**：同一分钟出现的两笔同额同分类支出（多半是记了两遍）。隔了几小时的两笔不算，午饭和晚饭不是重复。
2. **固定开销**：自动找出按周 / 两周 / 月 / 季 / 年规律出现的同额支出（房租、订阅、会员），漏记一到两期也能接上；给出「每月固定开销」和下次预计日期。
3. **断档月份 / 久未记账**：首尾之间几乎没记的整月；最后一笔距今超过两周。
4. **异常大额**：明显高于该分类平时水平的单笔（中位数 + 稳健 z 分数 + 倍数三重门槛）。
5. **分类不清**：近 3 个月支出里「其他」占比过高。
6. **月支出突增**：上个完整月比再上个月多花的部分，按分类拆开。

每条发现都能点「看这 N 笔」打开明细，再点进单笔编辑。算法是独立的纯函数模块 `js/modules/audit.js`，测试覆盖见 `tests/audit.test.js`（算法）与 `tests/audit-card.test.js`（卡片接入）；没有数据格式变化，旧备份照常导入。

1. **左滑删除不再带动整页上下滚**：以前手指从一条流水往左划想删它，屏幕经常先被整页滚动抢走，行被弹回；现在行自己判定方向——明显横向就锁给行，明显纵向才交还给页面。
2. 手感不变：左滑出「编辑 / 删除」、轻点开详情、长按 0.5 秒开操作表，都和之前一样。
3. 没有其它改动：数据、账本结构、备份格式完全不变，线上与本地各版本照常打开。

## 2.17.0 更新了什么（小助手）

1. **首页右上角多了 ✨ 小助手**：一句话就能记账——「午饭 35 微信」「昨天打车 18 支付宝」，也能一次说多笔（单批最多 20 笔）。
2. **写之前先给你看**：逐笔显示金额、分类、账户、日期、备注；默认值标「已按默认补全」，和已有账目相似会提醒你再确认；点「确认写入」才真正落库，多笔一次事务，任一笔不合法就整批不写入。
3. **不只是记账**：还能改（金额 / 分类 / 账户 / 日期）、改收支类型、删、查（「这个月餐饮花了多少」），查完可一键跳到明细分月。
4. **「记一笔」瘦身**：原来的「一句话」小输入框搬进了小助手，手动记账页更清爽。解析仍全部在本机完成——没有模型调用、没有网络请求；数据库结构未变，旧备份照常导入。

## 2.16.3 更新了什么（首页精简）

1. 首页删掉了那条「找流水 / 分类 / 待报销」快捷卡——这三个入口在明细页的工具行和底部标签里都能到，首页不再重复摆一份。
2. 首页现在从汇总头部直接接到本月预算卡，滚动更短；其余页面与数据不变，旧备份照常导入。

## 2.16.0 更新了什么（账单解读）

1. **底部导航改成 5 槽等宽**：首页 / 解读 / ＋ / 统计 / 我的，中间的黄色「＋」仍是记一笔，320px 小屏也不挤。
2. **新增「解读」页**：把当月账目翻成 7 个分区的本地规则报告——核心结论、收支摘要、消费结构、收支变化、值得留意、行动建议、统计口径；支持 本月 / 上月 / 近3个月 / 近6个月。
3. **图表能钻取**：环图扇区和图例可点出分类明细，柱状图点某个月直接切报告，明细里的某笔流水还能继续点开详情。
4. **首页预算卡常驻**：没设置时一键去设置，设置后显示已用 / 预算 / 剩余，超支变红；快捷入口收敛为三格，不再重复放预算。
5. 全部计算仍在本机完成，没有上传、没有新增账号；数据库结构未变，旧备份可直接导入。

## 2.13.0 更新了什么（照片三件事）

1. **画质 = 手机相册原图**：选照片时不再重新编码，直接把相册里的原始文件字节存下来（照片卡片上会标「原件」）。旧版本会把照片压到长边约 1600px / JPEG 0.75 再存，2.13.0 起不压了 —— 拍多少存多少。
2. **张数不再限制**：一笔流水原来最多 3 张照片，现在不限张数（一次多选、分批添加都行）。缩略图按需解码、原图按需读取，几十张也不会把页面卡死。
3. **点开照片是全屏看原图**：点缩略图直接进全屏查看器，看到的 100% 是原图（不是放大后的缩略图），可以左右滑动、双指放大，点空白或按返回键退出。

两点提醒：

- 想看全屏原图用**相册右侧的缩略图**点开；如果点的是笔记／流水列表里的那张小图，走的也是同一条全屏通道。
- **以前存的照片不会自动变清晰** —— 旧版本已经压过再存进 IndexedDB 的照片，原图字节在原文件被清理后就找不回来了。新拍新选的照片从 2.13.0 起才是原图级。

## 为什么是这样一个仓库

这个仓库就是应用的全部源码：没有构建步骤、没有后端、没有第三方依赖，根目录下的文件 push 到 `main` 就直接发布到 GitHub Pages。之所以需要一个线上地址，是因为 Service Worker 只在 HTTPS 这样的安全上下文里才能注册——没有 HTTPS 就没有真正的离线能力。

## 文件

| 路径 | 作用 |
| --- | --- |
| `index.html` | 应用入口（壳层 JS/CSS 全部内联，约 1.27 MB） |
| `js/screens/` | 11 个页面文件（首页、记一笔、明细、统计、日历、报告、账户、账本、预算、设置、小助手），进入对应页面时才加载 |
| `js/modules/` | 10 个共用模块（数字键盘、图标选择、图表、一句话解析、助手内核、月度指标与提示词、习惯记账建议、账单 CSV 解析、账单体检、行内编辑），被页面按需加载 |
| `sw.js` | Service Worker，预缓存 35 项资源（入口 + 21 个页面/模块文件 + 静态资源）；导航请求网络优先、8 秒超时回退缓存 |

| `splash/` | iPhone 启动图 8 张 |
| `.nojekyll` | 关掉 GitHub Pages 的 Jekyll 处理 |

## 离线是怎么做到的

首次打开时 Service Worker 把上面这 35 项全部拉进本地缓存：

1. 之后任何一次打开（包括从主屏幕冷启动）都是先读缓存，**不依赖网络**；
2. IndexedDB（库名 `xzb2`）存账本、流水、预算、存钱目标，与网络无关；
3. 联网有新版时后台更新缓存，下次打开生效——所以偶尔需要重开两次才能看到新版本。

实测：断网状态下冷启动约 0.3 秒渲染完成，写入一笔流水后重载仍然存在。

## 隐私

- 没有埋点、没有第三方脚本；完整账目默认只存在本机，不上传任何服务器。
- **内置在线模型默认开启**：首次打开自动配好内置千问 MaaS 端点并开启，视为已同意应用内隐私告知；用小助手 / AI 解读时，当轮原话、账户名、分类名会发往该第三方端点。内置密钥是公开的（随仓库发布），任何人都能看到并调用，免费余量可能被刷掉；介意可在「我的 → 助手 → 在线模型」关闭或换成自己的密钥，自定义配置不会被覆盖。
- **云备份默认关闭**：填了你自己的 GitHub 密钥才出网，数据只进你自己的私有 Gist（私有 Gist 只是不公开索引，不是加密存储）。
- 完整账目不存任何服务器（开了云备份则在你自己的 Gist 里）。清除 Safari 网站数据、或从主屏幕删除应用，本机数据会一起消失。
- 因此唯一可靠的备份方式是应用内 `我的 → 导出备份 → 导出 JSON`，请定期导一份存到「文件」或 iCloud。

## 装到手机上的步骤

1. iPhone 用 **Safari**（不是微信内置浏览器）打开上面的地址，等首页数字出现；
2. 点底部「分享」→「添加到主屏幕」→ 命名「小账本」→ 添加；
3. 从主屏幕图标启动一次，让它把离线缓存装完（第一次启动会闪一下启动图）；
4. 想验证真离线：开飞行模式，从主屏幕冷启动，能进「首页」并记一笔就成了。

## 更新

站点内容由这些文件直接推送，更新方式是把入口、`sw.js` 与 21 个页面/模块文件同批推送（少推一个对应页就打不开）；缓存名带版本号，新 SW 激活时会清掉旧缓存。推送完成后手机上可能需要重开两次页面才会切到新版。逐版改了什么见 [CHANGELOG.md](CHANGELOG.md)。
